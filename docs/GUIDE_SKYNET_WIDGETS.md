# Гайд: как писать команды для Skynet и виджеты для дашборда

Этот документ объясняет, как правильно писать плагины для:
- **Команд флота Skynet** (массовые действия на серверах)
- **Виджетов дашборда** (дополнительные блоки информации в главном экране)

---

## 1. Плагины Skynet (команды для флота)

### 1.1. Структура и категоризация

Все команды для Skynet находятся в директории `plugins/skynet_commands/`. Они **обязательно** должны быть сгруппированы по поддиректориям, которые определяют их категорию в меню.

- `plugins/skynet_commands/system/`
- `plugins/skynet_commands/diagnostics/`
- `plugins/skynet_commands/security/`
- и т.д.

Скрипт `modules/skynet/executor.sh` автоматически:
- рекурсивно сканирует эти директории;
- использует названия поддиректорий как **заголовки категорий** в меню;
- находит все исполняемые `.sh` файлы;
- читает из них заголовок (`# TITLE:`) и формирует пункты меню;
- по выбору пользователя копирует файл плагина на удалённый сервер, выполняет его там и удаляет.

### 1.2. Структура плагина и функция `run()`

Плагин — это обычный bash-скрипт. `Executor` выполняет его как единый файл (`bash plugin.sh`).

**Простой плагин (без функции `run()`):**
```bash
#!/bin/bash
# TITLE: Показать аптайм сервера

# Этот плагин будет показан в меню "diagnostics"
# под названием "Показать аптайм сервера".

uptime -p
```

**Плагин с функцией `run()`:**
```bash
#!/bin/bash
# TITLE: Полное обновление системы

run() {
    echo "Запускаю обновление системы (apt)..."
    apt-get update -qq && apt-get upgrade -y -qq
    echo "Обновление завершено."
}

# Запускаем главную функцию
run
```
> **Примечание:** Оборачивание логики в функцию `run()` является хорошей практикой для сложных плагинов, но не является техническим требованием. Простые плагины, как в первом примере, могут выполнять команды напрямую.

### 1.3. Метаданные плагина

- **`# TITLE: <Название>` (Обязательно)**
  Человекочитаемое имя, которое увидит оператор в меню Skynet.

- **`# SKYNET_HIDDEN: true` (Опционально)**
  Если указано `true`, плагин будет **скрыт** из общего меню команд. Это используется для системных плагинов, которые должны вызываться только программно из других модулей.

- **`# SKYNET_COLOR: <цвет>` (Опционально)**
  Подсвечивает пункт в меню «Выполнение команды на флоте», чтобы важные или долгие команды не терялись в общем списке. Допустимые значения: `yellow`, `green`, `cyan`, `red`, `blue`, `magenta` (`purple`), `gray`, `bold`. Неизвестное имя или отсутствие заголовка — обычный цвет меню.

  Цвет задаётся именно в плагине, а не номером пункта в коде меню: номера пунктов сквозные и едут, как только добавится или скроется любой другой плагин.

### 1.4. Скрытые плагины и передача параметров

Скрытые плагины — это основной способ выполнять сложные, параметризованные задачи на удаленных серверах без интерактивного ввода. Параметры передаются через переменные окружения.

**Пример вызова из модуля (смена порта SSH):**
```bash
# Внутри какого-либо модуля в modules/
local new_port="2223"
local server_name="my-server-1"
local env_vars=("NEW_SSH_PORT=${new_port}")

_skynet_run_plugin_on_server "security/02_change_ssh_port.sh" "$server_name" "${env_vars[@]}"
```

**Пример скрытого плагина (`plugins/skynet_commands/security/02_change_ssh_port.sh`):**
```bash
#!/bin/bash
# TITLE: Сменить порт SSH
# SKYNET_HIDDEN: true

# Плагин читает переменную окружения NEW_SSH_PORT
# и выполняет неинтерактивную смену порта.

if [[ -z "$NEW_SSH_PORT" ]]; then
    echo "Ошибка: новый порт не задан."
    exit 1
fi

echo "Меняю порт SSH на ${NEW_SSH_PORT}..."
sed -i "s/^#\?Port .*/Port ${NEW_SSH_PORT}/" /etc/ssh/sshd_config
systemctl restart sshd

echo "Порт успешно изменен."
```
Этот механизм позволяет создавать мощные внутренние API для управления серверами флота.

## 2. Виджеты дашборда

### 2.1. Где лежат и как работают

- **Расположение:** `plugins/dashboard_widgets/`
- Каждый исполняемый `.sh` файл — это отдельный виджет.
- **Принцип работы:** Модуль `ui/dashboard.sh` запускает **включенные** виджеты, кэширует их вывод и отображает в формате `Метка : Значение` с автоматическим выравниванием.

Управление виджетами (включение/выключение) находится в главном меню `[w] 💡 Управление виджетами`.

### 2.2. Структура виджета

```bash
#!/bin/bash
# TITLE: Название виджета по-русски
# Краткое описание, что он показывает.

# Подключаем общие хелперы для доступа к ensure_dependency
if [[ -n "$SCRIPT_DIR" ]]; then
    source "${SCRIPT_DIR}/modules/core/common.sh" &>/dev/null
fi

# Убедимся, что у нас есть нужные утилиты (пример)
ensure_dependencies "curl" "jq"

# ... основная логика виджета ...

# Вывод должен быть в формате "Заголовок: Значение"
echo "Мой параметр: 123"
```
- **`# TITLE: ...`**: Имя виджета, которое отображается в меню управления.
- **Формат вывода**: `Название : Значение`. Двоеточие является обязательным разделителем.
- **Зависимости**: Рекомендуется использовать хелпер `ensure_dependencies "утилита1" "утилита2"` для автоматической установки недостающих пакетов (`curl`, `jq` и т.д.). Для этого нужно в начале виджета подключить `common.sh`.

### 2.3. Пример виджета (Курс BTC)

Файл: `plugins/dashboard_widgets/01_crypto_price.sh`

```bash
#!/bin/bash
# TITLE: Курс биткоина (BTC)
# Виджет для дашборда: показывает цену BTC в USD и RUB.

# Подключаем общие хелперы для доступа к ensure_dependency
if [[ -n "$SCRIPT_DIR" ]]; then
    source "${SCRIPT_DIR}/modules/core/common.sh" &>/dev/null
fi

# Проверяем и при необходимости устанавливаем curl и jq
ensure_dependencies "curl" "jq"

API_URL="https://api.coingecko.com/api/v3/simple/price?ids=bitcoin&vs_currencies=usd,rub"

RESPONSE=$(curl -s --connect-timeout 3 "$API_URL")
PRICE_USD=$(echo "$RESPONSE" | jq -r '.bitcoin.usd' 2>/dev/null)
# ... остальная логика форматирования ...

echo "Курс BTC: \$${USD_FMT} / ₽${RUB_FMT}"
```
